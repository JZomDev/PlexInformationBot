# Setup UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a newcomer configure PlexInformationBot from a locally hosted, mobile-friendly web page with per-section Test buttons, plus `/setup...` slash commands that save their own Discord message IDs.

**Architecture:** A `Settings` record is stored as JSON in a config folder and merged over the existing environment variables (file wins per field). A JDK `HttpServer` serves a static page and a small JSON API behind a form login; it starts before, and independently of, the Discord bot. The bot becomes restartable so a Save applies without restarting the container.

**Tech Stack:** Java 17, Gradle Kotlin DSL, Javacord 3.8.0, javaplex 6.1.0, Gson 2.10.1 (record support), `com.sun.net.httpserver`, `java.net.http.HttpClient`, `javax.crypto` PBKDF2. New test-only dependency: JUnit 5 (`org.junit.jupiter:junit-jupiter:5.10.2`). No other new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-25-setup-ui-design.md`

**Gate command** (no local Java; runs in a container, cache volume avoids re-downloading Gradle):
`docker run --rm -v "$PWD":/w -w /w -v plexbot-gradle:/root/.gradle eclipse-temurin:17-jdk sh gradlew test --no-daemon -q`

## Global Constraints

- Java source compatibility 17; package root `org.example`.
- Web port default `4546`, overridden by env `WEB_PORT`. Config folder default `/config`, overridden by env `CONFIG_DIR`.
- Files in the config folder: `settings.json`, `credentials.json`.
- Default login `admin` / `admin` when `credentials.json` does not exist; the first successful login forces a username and password change, which creates the file; deleting the file restores `admin` / `admin`.
- Passwords: salted PBKDF2 (`PBKDF2WithHmacSHA256`), never stored or logged in plain text. Session cookie: `HttpOnly`, `SameSite=Strict`, `Secure` only when the request has `X-Forwarded-Proto: https`. Every state-changing API request needs header `X-CSRF-Token` equal to the session's token. `X-Forwarded-For` is not trusted.
- The 15 existing env vars keep working as fallback: `BOT_TOKEN, IP, PORT, PLEX_KEY, ROLE_ID, TEXT_CHANNELID, MESSAGEID, API_KEY, TAUTULLI_URL, QUEUE_TEXT_CHANNELID, QUEUEMESSAGEID, RADARR_URL, RADARR_API, SONARR_URL, SONARR_API`.
- Precedence is per field: a non-empty field in `settings.json` wins; otherwise the env var. An empty form field means "unset".
- Secrets (`botToken, plexToken, tautulliApiKey, radarrApiKey, sonarrApiKey`) are sent to the page as `********`; a submitted `********` keeps the saved value.
- Role message text constant stays `React to this message to get your roles!`; reaction emoji stays the clapperboard.
- Slash commands `/setupreact` (role option), `/setupstatus`, `/setupcontentqueue`: admin-only, registered per server; `/activestreams` stays global.
- The page must work at phone width. No separate frontend build step.
- No Discord token, Plex token or API key appears in full in logs, API responses or error messages.

## Review Focus

1. `settings.json` is corrupt or unreadable: the page and login must still come up (env fallback, a visible warning), never a crash. (Task 1)
2. Config folder is read-only or the disk is full: Save must return a clear error, not silently drop changes. (Task 1, Task 4)
3. Test or error messages that echo a URL or exception containing a token or key must be masked. (Task 5)
4. Password edge cases: blank, `admin`, shorter than 8 characters, very long (over 1000 characters), unicode usernames. (Task 2)
5. Double-clicking Save, or Save while the bot is still starting: restarts must serialise, not leave two Discord connections. (Task 6)
